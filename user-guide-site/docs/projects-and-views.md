# Projects and Views

Projects are the main containers for work. Each project gathers tasks, people, due dates, and progress in one place.

<img src="/user-guide/img/user-guide/projects.png" alt="Projects list" />

## The Projects screen

Use the Projects screen to:

- Review all projects you can access.
- See project status and date range at a glance.
- Mark important projects as favorites.
- Open a project dashboard, detail view, or edit screen.

## Favorite important projects

Use the pin action in the project row to mark a project as a favorite. Turn on `Show only Favorites` when you want a shorter list.

## Create a project

Select `Create` from the Projects page to open the project form.

<img src="/user-guide/img/user-guide/project-create.png" alt="Create project form" />

When creating a project:

- Give it a clear `Project Name`.
- Add a short description so others understand the purpose.
- Choose the project `Status`.
- Set start and end dates.
- Decide whether the project is private or shared with departments, teams, or observers.

:::note Access and assignments
Project access and task assignment are not always the same thing. A task can still be assigned to a user even if that person does not have project access through the current private, department, team, or observer settings.
:::

## Choosing who can see the project

The access choices on the project form help you control who can work in the project and who should only stay informed.

- Use `Private Only For Me` when you are drafting a project, planning work before it is ready to share, or keeping a personal working project that does not need other contributors yet.
- Use `Observers` when people should be able to follow progress without being part of the working team. This is useful for managers, approvers, executives, or stakeholders who need visibility but are not updating tasks every day.
- Use `Departments` when the project should be visible to a broader business area, such as Marketing, Operations, or Product. This works best when many people in the same department may need to review or contribute over time.
- Use `Teams` when the project is for a smaller, defined working group. This is the better choice when the work belongs to one delivery team, squad, or cross-functional project group.

## Common sharing patterns

- Choose `Private Only For Me` if the project is still in draft and you want to finish the setup before others see it.
- Choose a private project with `Observers` if you want to manage the work yourself but still let leadership or reviewers track progress.
- Choose `Departments` when the project needs wider visibility across a function and several people may join or review work.
- Choose `Teams` when the project has a fixed group of contributors who will actively work on tasks together.

:::tip Simple rule
If people need to do the work, add the right team or department. If they only need to stay informed, add them as observers.
:::

:::note Calendar colors
The color you see for a project in calendar views comes from the project color selected on the project form. Calendar colors do not represent task status or priority.
:::

## Inside a project

Open a project to work with its tasks in different ways:

- `List` view for quick scanning and bulk review.
- `Board` view for moving work by status.
- `Gantt` view for schedule planning.
- `Project Dashboard` for charts and workload summary.

:::tip Best practice
Use the project dashboard when you want a summary for a meeting, and use the task list or board when you are actively updating work.
:::

## Create tasks from Project view

When you are inside a project, use `Add Task` from the task toolbar.

<img src="/user-guide/img/user-guide/Create Task.png" alt="Create Task form with required fields highlighted" />

Required fields to submit:

- `Title`
- `End Date`

:::note About Project field
When creating from Project view, the `Project` is already preselected. If you create from a global task list instead, selecting `Project` is also required.
:::

When creating a task:

- Add a clear title so it is easy to scan in list and board views.
- Set `Status` and `Priority` first so the task lands in the right lane and urgency level.
- Set realistic start and due dates.
- Assign an owner in `Assigned To`.
- Use `Parent Task` only when this is a true subtask.
- Add details in description and additional information so updates are easier later.

:::note Project status limits task creation
If a project is already marked `Done` or `Cancelled`, new task creation is blocked.
:::

## Task List view in Project view

`List` view is best when you need detail and control.

In Task List view you can:

- See tasks grouped by status sections.
- Collapse or expand each status section.
- Scan key fields quickly: assignee, start date, due date, priority, and current status.
- Open task details from the task name or `View` action.
- Use `Edit` and `Delete` from the action column.
- Expand parent tasks to show subtasks inline.

## Tip: use the status circle for quick completion

In the left side of each task row, there is a small status circle.

<img src="/user-guide/img/user-guide/task-list-complete-circle-tip.svg" alt="Task list row showing the status circle used to mark tasks done" />

- Click the circle to mark a task as `Done` quickly.
- A check mark in the circle means the task is already done.
- For parent tasks, completion is blocked until all child tasks are done.
- If you marked a task done by mistake, open `Edit Task` and change the status back.
